# GPT 후속 설계 검토

- 날짜: 2026-10-18
- 검토자: 현재 Codex 대화의 GPT. 별도 외부 GPT 서비스나 Gemini 응답을 사용한 기록이 아니다.
- 사용자 결정: Gemini는 다른 계정에 있으므로 접근 경로를 더 요구하지 않고 GPT로 후속 검토한다. 기존 Grok 응답은 참고 자료로 보존한다.
- 범위: 현재 저장된 코드, 기존 실제 재생 기록, SNS 코어 재현 시험. 이번 검토에서 YouTube를 다시 재생하거나 SNS에 연동하지 않았다.
- 유지 조건: 실제 더빙은 로컬 Gemma 4 E4B + Supertonic 3 생성 1.15배다. 설계 검토에 GPT를 사용하는 결정은 더빙 번역 엔진 변경이 아니다.

## 판단

어댑터를 추가하기 전에 **작업 수명과 음성 자원 소유권을 명확히 해야 한다.** 브라우저 큐가 유한하다는 사실만으로 서버 추론 대기가 유한하거나 Stop 뒤 소리가 절대 나오지 않는다고 보장할 수 없다. 다음 제품 단계는 선택한 텍스트 한 건 읽기와 YouTube 어댑터 계약 검증으로 제한한다.

## 코드에서 확인한 문제와 반론

| 항목 | 확인한 사실 | 판단·조치 |
|---|---|---|
| 큐 정보 변경으로 제한 우회 | `media-session.js`가 호출자의 clip 객체를 그대로 정렬·합산했다. 4초 항목을 넣고 duration=0으로 바꾸면 5초 제한에 다른 4초 항목도 들어갔고, start 변경으로 순서도 바뀌었다 | **재현 후 수정.** 수락 당시 id/start/duration을 내부 항목에 복사한다. 원래 객체는 자원 해제를 위해 별도 참조한다 |
| UI 취소와 서버 취소의 차이 | background의 prepare fetch는 90초 timeout, 로컬 모델 요청은 120초 timeout을 사용한다. prepare 경로에 UI 세션 취소를 전달하는 연결은 없다 | 서버 jobId·세션·취소 신호를 연결하고 대기 작업을 제거해야 한다. timeout을 짧게 하는 것만으로 해결되지 않는다 |
| 첫 음성 반환 지연 | 서버는 요청 구간들의 번역을 모두 받은 다음 TTS 묶음을 완료해 응답한다 | 현재 문장 1개를 우선 준비하고 나머지를 선행 작업으로 분리하는 후보를 검증한다. 번역·검증을 끝내지 않은 토큰 스트림을 바로 읽지는 않는다 |
| 큐에서 꺼낸 음성의 소유권 | `take` 이후 항목은 큐에 없고 Stop의 queue clear 대상도 아니다 | 출력 어댑터가 재생/디코딩 자원을 소유하고 Stop·탐색에 즉시 해제해야 한다. await decode 이후, 실제 출력 직전에 세대를 다시 검사해야 한다 |
| 중복 처리의 범위 | 현재 중복 검사는 큐에 남은 항목에만 적용된다 | 실제 어댑터에는 재생 중/완료 항목의 중복 억제가 필요하다. 장시간 라이브에서 이력만 무제한 쌓지 말고 캡처 순서와 폐기 기준을 함께 정의한다 |
| 의미 보존 판정 | 수량·필수어·일부 문형 검사가 있고, 영상별 교정과 문맥 힌트는 제한된 사례에 근거한다 | 모든 부정·조건·비꼼을 검사한다고 확대 해석하지 않는다. 사용자 확인을 거친 원문·정답 쌍으로 별도 코퍼스를 만든다 |

첫 준비 11.64초와 캐시 재시작 1.26초는 기존 서로 다른 조건의 관측이다. **묶음 응답 구조는 지연 후보이지만 11.64초의 원인을 모두 설명한다고 확정할 수 없다.** 단계별 계측 없이 모델을 교체하거나 병렬 요청 수를 늘리는 것은 우선순위가 아니다. STT와 번역의 자원 경쟁이 오히려 다음 음성을 늦출 수도 있으며, 이는 측정할 가설이다.

## 수정한 코어의 경계

`lib/media-session.js`는 큐 내부의 집계·정렬·중복 신원을 외부 객체 변경에서 분리했다. 거절된 응답이 이미 큐가 소유한 동일 자원을 해제하지 않는 기존 보호도 유지했다. 회귀 시험은 객체 변경 후 대기 초수, 새 항목 거부, 중복 거부, 정렬, Stop 시 원래 자원 해제를 확인한다.

이 변경은 큐 계약의 일부다. `take`가 반환한 원래 객체의 소비, 디코딩, 재생 완료 이력과 서버 취소까지 구현한 것은 아니다. 실제 SNS 제품에 연결하기 전 어댑터 계약에서 이 책임을 구현하고 시험한다.

## 다음 구현 순서

1. **계측·작업 수명**: sessionId/jobId와 각 단계의 대기·실행·준비 시각을 기록한다. 현재 위치의 요청을 우선하고 취소된 대기 작업을 제거한다. 취소할 수 없는 엔진의 실행 슬롯은 실제 종료까지 점유한다.
2. **첫 음성 준비 실험**: 같은 원문·설정·캐시 상태에서 현재 묶음 방식과 첫 문장 우선 방식을 비교한다. 시작 지연뿐 아니라 이후 60초 버퍼 부족과 문장 끝 대기를 함께 측정한다. 의미 검사는 유지한다.
3. **어댑터 계약**: prepare, decode, 출력 직전 각각에서 영상 신원·세대·설정 개정을 확인한다. 언어/목소리 변경도 이전 결과를 무효화한다. Stop은 서버 완료를 기다리지 않고 소리부터 끊는다.
4. **선택한 영문 글 한 건**: X/Reddit 피드 전체 자동 처리가 아닌, 사용자가 선택한 텍스트를 로컬 번역 후 읽는 첫 기능을 구현한다. 읽기 중 선택 대상 변경·Stop을 시험한다.
5. **영상과 캡처**: 선행 자막 VOD와 현재 소리만 얻는 지연 해설을 분리한다. 캡처는 원음 복구·자기 피드백·긴 침묵 시험을 통과한 뒤 연결한다.

이는 구현 계획이며 실행 완료 항목 목록이 아니다. 1.15 생성 속도를 유지한 상태에서 의미를 살리려면 긴 문장의 영상 대기 또는 지연 해설 누적을 별도 지표로 공개해야 한다. 추가 가속으로 수치를 숨기지 않는다.

## 이번 검증

- 변경 전 객체 변경 재현: 원래 4초 음성 두 개가 5초 큐에 수락되고, 집계는 4초로 표시됨.
- 변경 후 `npm run test:regressions`: **53/53 통과**.
- `npm run check`: **JavaScript 34개 문법 통과**.
- `git diff --check`: 공백 오류 없음, 기존 줄바꿈 형식 안내만 출력.
- 실행 중인 YouTube 경로에 이 프로토타입은 연결되어 있지 않다. 백엔드 재시작이나 확장 새로고침은 하지 않았다.
