# Grok Build 실제 검토 응답

- 요청일: 2026-10-18 KST
- 경로: https://grok.com/c/9c209f20-d2e1-44d4-9210-1d167e814663
- 화면 선택: Build. 공식 Grok 4.7 가이드는 Build 기본 모델을 Grok 4.7로 안내한다. 웹 UI에서 원시 모델 ID는 제공되지 않았다.
- 실제 브라우저/성능 검증이 아닌 모델의 설계 검토 의견이다. 아래 제안은 별도 비판 검토를 거쳐 채택한다.

결론부터 말하면, 이 초안은 지금 YouTube watch의 캡션 VOD를 어댑터 뒤로 옮기는 범위에서만 성립합니다. 캡션이 미리 주는 4문장 준비, 영상 `currentTime` 정렬, 1.15 고정, 마지막 음절을 위한 일시정지를 자막 없는 탭 캡처·라이브·피드·텍스트 게시물에 그대로 쓰면 브라우저가 주지 않는 능력을 약속하게 됩니다. 이 문서는 프로토타입을 실행하거나 지연·음질을 측정한 결과가 아닙니다.

## 근거로 쓰는 사실과 모르는 것

확인한 공식 동작은 다음과 같습니다.

- `chrome.tabCapture`는 사용자가 확장 프로그램을 실행한 뒤의 탭 미디어 스트림입니다. 스트림을 얻으면 그 탭의 오디오는 사용자에게 더 이상 재생되지 않습니다. 공식 설명은 `getDisplayMedia()`의 `suppressLocalAudioPlayback: true`와 같다고 합니다. 다시 들려주려면 캡처 스트림을 직접 출력에 연결해야 합니다. 출처: [tabCapture](https://developer.chrome.com/docs/extensions/reference/api/tabCapture), [screen capture 안내](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture).
- `getMediaStreamId()`의 ID는 한 번만 쓸 수 있고, 쓰지 않으면 몇 초 만에 만료됩니다. Chrome 116부터 서비스 워커가 받은 ID를 offscreen 문서에서 소비할 수 있습니다. `targetTabId`는 activeTab이 허용된 탭만 됩니다. `capture()`는 탭 탐색 이후에도 유지되고, 탭이 닫히거나 스트림을 닫을 때 멈춥니다. `getCapturedTabs()`는 기존 캡처 때문에 새 캡처가 실패할 수 있음을 알리려고 있습니다.
- offscreen 문서는 `chrome.runtime`만 확장 API로 쓸 수 있습니다. `AUDIO_PLAYBACK` 이유는 오디오가 약 30초 없으면 문서를 닫습니다. 다른 이유는 그 수명 제한이 없다고 되어 있습니다. 이유를 여러 개 줄 때의 우선순위는 확인하지 못했습니다. 출처: [offscreen](https://developer.chrome.com/docs/extensions/reference/api/offscreen).
- `HTMLMediaElement.captureStream()`은 그 요소에서 지금 렌더링 중인 내용을 실시간 캡처합니다. 아직 재생하지 않은 버퍼의 PCM을 돌려준다는 설명은 없습니다. 출처: [MDN captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/captureStream).
- 콘텐츠 스크립트의 네트워크 요청은 페이지 오리진의 요청이고, 확장 프로그램에 호스트 권한이 있어도 크로스 오리진으로 취급됩니다. 출처: [Cross-origin network requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests).
- 선택 권한은 사용자 제스처 안에서 `permissions.request()`로 요청합니다. 출처: [permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions).

모르는 것으로 남기는 항목: Whisper, Gemma, Supertonic의 처리 시간, 사이트별 DOM·음소거·광고 신호, EME 영상에서 탭 캡처가 복호된 소리를 포함하는지, 페이지에 넣은 `<audio>`가 항상 탭 믹스에 들어가는지, offscreen 재생이 탭 캡처에 절대 안 섞이는지, 라이브 플레이어를 잠깐 멈춘 뒤 재생 위치가 점프하는지, 2026-10-18 현재 Local Network Access가 기본으로 차단되는지. 2025-06 Chrome 문서의 LNA는 Chrome 138에서 플래그 opt-in이었습니다. 출처: [Local Network Access](https://developer.chrome.com/blog/local-network-access).

## 1. 가장 심각한 실패 모드

**1. 캡션용 선행 계약을 인과 캡처에 재사용한다.**
탭 캡처와 `captureStream()`은 이미 나오고 있는 소리만 줍니다. 4문장을 미리 만들려면 미래의 글이나 미래의 PCM이 필요합니다. 반례: 클릭 시각의 발화가 `t=0`에 시작해 `t=3`에 끝납니다. 캡처는 `t=3` 이전에 그 문장 전체를 가질 수 없고, 모델 시간이 0보다 크면 한국어는 `t=0`에 맞춰 시작할 수 없습니다. “90초 STT 창”이 플러시 간격이면 첫 재생은 그 창이 찬 뒤입니다. 직전 문맥 길이라면 미래 문장을 만들지 못합니다. 하나의 숫자로 둘을 겸하면 안 됩니다.

**2. 탭은 즉시 묵음이 되고, 더빙은 다시 캡처되거나, 복구 없이 끊긴다.**
캡처가 시작되면 원음은 공식 동작으로 끊깁니다. 첫 TTS 이전은 무음입니다. TTS를 페이지 안에 재생하고 그 소리가 탭 믹스에 들어가면, STT가 방금 만든 한국어를 다시 받아 번역이 발산할 수 있습니다. 페이지 삽입 오디오의 포함 여부는 문서가 요소 단위로 보장하지 않으므로 실측 전제입니다. 반대로 TTS를 `AUDIO_PLAYBACK`만 있는 offscreen에 두고 문장 사이 침묵이 30초를 넘으면 문서가 닫힐 수 있습니다. 닫힌 뒤 탭 음소거가 풀리는지는 문서에 없습니다. 반례: 모델이 멈추거나 대사가 없는 구간이 35초이면, 원음도 더빙도 없는 상태가 될 수 있습니다. 재시작은 제스처가 다시 필요할 수 있습니다.

**3. 미디어 신원이 seek용 epoch보다 자주 바뀐다.**
캡처는 탐색을 넘어 유지됩니다. 피드 교체, Shorts형 자동 넘김, 광고는 문서와 탭은 그대로인데 시간 축만 0으로 돌아갑니다. 반례: 영상 A의 1.2초용 TTS가 epoch를 “seek”에만 올리면 영상 B의 1.2초에 재생됩니다. 광고와 본문이 한 `<video>`를 공유하면 광고 음성이 본문 자막 큐에 섞입니다. 탭 캡처는 요소를 고르지 못하므로, 소리 나는 영상이 둘이면 믹스가 그대로 STT 입력이 됩니다.

**4. JS epoch는 로컬 추론을 멈추지 않는다.**
폐기를 재생 직전의 검사로만 하면, seek 여러 번이 CUDA 작업을 그대로 쌓습니다. 유한한 JS 큐는 GPU와 Node 쪽 대기열을 제한하지 못합니다. 반례: 2초 동안 seek가 5번이고 Whisper가 취소되지 않으면, 늦은 응답이 새 epoch 검사 직전에 스케줄되거나, 검사하더라도 다음 문장의 시작을 지연시킵니다. 역압은 엔진 in-flight 상한과 취소가 있을 때만 성립합니다.

**5. “짧게, 의미는 유지”는 검사 없이 재생하면 가장 나쁜 오류를 숨긴다.**
길이를 줄이라는 목표는 부정, 조건, 숫자를 버릴 이유입니다. 반례: “Don't buy above 16.5”가 “16.5에 사라”로 바뀌어도 한국어로는 자연스럽습니다. 고유명사도 번역·음차·환각을 구분할 계약이 없습니다. 1.15는 이미 만들어진 파형의 길이만 줄이며, 빠진 부정문을 복구하지 않습니다.

## 2. 탭 캡처, 1.15, 저지연은 동시에 안 된다

가능한 관계만 적으면 이렇습니다. 원문 발화가 `[t0, t1]`에 재생된다고 할 때, 캡처 경로에서 그 발화의 마지막 샘플은 `t1` 이전에 오지 않습니다. 준비 시각은 `t1`에 끝점 검출 대기, STT, 번역, TTS를 더한 값이고, 각 항은 0 이상입니다. 실제 값은 모릅니다. 1.15는 그 이후에 생긴 오디오의 재생 길이를 `한국어 길이 / 1.15`로 만들 뿐입니다.

그래서 다음 약속은 불가능합니다.

- 자막 없이, 캡션 경로와 같은 4문장 선행.
- 아직 재생되지 않은 플레이어 버퍼를 탭 캡처로 듣기. 버퍼 구간을 알 수 있는 표준 시계와, 그 구간의 PCM을 주는 표준 읽기는 별개입니다. 후자는 확인되지 않았습니다.
- 고정 1.15만으로, 영상은 항상 1배속이고, 지연은 낮으며, 마지막 음절은 항상 보존. 한국어가 슬롯보다 길면 홀드, 겹치기, 잘라내기 중 하나가 필요합니다. 홀드 동안 “플레이어는 1배속”은 이미 거짓입니다.
- 라이브에서 홀드로 음절을 지키고 실시간 위치도 지키기. 홀드가 가능한지는 플레이어마다 다르며, 여기서 검증하지 않았습니다. 서버의 라이브 에지는 일시정지 동안 진행될 수 있습니다.

성립하는 것은 모드를 나누는 일입니다. 캡션 VOD는 듣기 전에 글을 스케줄할 수 있고, 이때의 선행 한계는 번역과 TTS입니다. 캡처 VOD는 끝점 이후의 지연 더빙이며 선행 깊이는 이미 들은 발화뿐입니다. 라이브는 늦은 결과를 버리고 홀드를 쓰지 않습니다. 1.15는 동기 제어기가 아니라 말속도 기본값입니다. 동기 제어기는 시작 시각, 홀드, 폐기입니다.

## 3. 재캡처, 피드, 라이브, 충실도, 원음

**재캡처.** 안전한 미검증 가정은 이것입니다. PCM 캡처 그래프와 TTS 출력 그래프를 분리하고, TTS는 offscreen의 목적지에서만 재생합니다. 공식 예제도 캡처 스트림을 offscreen `AudioContext`에 연결해 사용자에게 다시 들려줍니다. 페이지로 더빙을 주입하는 경로는 만들지 않습니다. 합격 절차는 표식 톤을 TTS로만 내고, 캡처 PCM에 그 톤이 없는지를 보는 것입니다. 이 검토는 그 절차를 실행하지 않았습니다.

**여러 영상, 광고, 피드 교체.** 어댑터 출력은 URL이 아니라 세대가 있는 불투명 `mediaId`여야 합니다. 활성 영상은 휴리스틱이므로 틀린 경우를 코어가 고칠 수 없습니다. 두 요소가 동시에 가청이거나 광고인지 모르면 세션은 “더빙 안 함”이어야 하며, 모르는 소리를 STT 큐에 넣으면 안 됩니다. 탭 캡처를 켜기 전에 비활성 영상이 음소거인지 어댑터가 관찰해야 합니다. 관찰할 수 없으면 요소 단위 캡처도 표준상 실시간일 뿐이고, 크로스 오리진·EME에서 오디오가 비는지는 사이트별로 모릅니다.

**VOD와 라이브.** VOD 캡션만 안정적인 미래 cue와 홀드를 쓸 수 있습니다. 라이브 자막은 개정됩니다. 같은 cue id라도 `revision`이 달라지면 이전 TTS는 폐기합니다. 라이브 캡처는 큐에 미재생 항목을 쌓지 않습니다. 텍스트 게시물은 영상 시계가 없습니다. `currentTime` 없는 비디오 세션으로 넣으면 스크롤과 seek 취소가 섞입니다.

**부정, 숫자, 고유명사.** 재생 전 순수 함수가 필요한 슬롯을 검사합니다. 숫자는 값, 부정은 극성, 고유명사는 미리 정한 표기만 통과시킵니다. 실패하면 그 문장은 말하지 않습니다. 짧은 의역으로 대체하지 않습니다. 모델 프롬프트만으로는 합격 기준이 되지 못합니다. 코퍼스 합격률은 측정값이 없으므로 적지 않습니다.

**원음 보존.** API는 보존을 해 주지 않고, 기본으로 탭을 묵음으로 만듭니다. 선택지는 셋입니다. 대체: 원음을 다시 연결하지 않고 TTS만 재생합니다. 혼합: 캡처 스트림을 offscreen에서 낮은 게인으로 다시 연결하고 TTS 동안만 덕킹합니다. TTS는 그 캡처 그래프에 넣지 않습니다. 페이지 혼합: 재캡처 위험이 있으므로 금지합니다. 캡션 경로에서는 탭 캡처를 열지 않으면 플레이어가 원음을 계속 재생합니다. 이것이 현재 YouTube 동작을 덜 깨는 길입니다.

## 4. 순서와 합격 기준

한 번에 X, Reddit, Instagram, TikTok, Shorts를 붙이지 않습니다. 사이트 선택 권한은 맞지만, 호스트 권한이 탭 캡처 제스처를 대신하지 않습니다. loopback 호출은 콘텐츠 스크립트가 아니라 확장 오리진에서 합니다. 페이지 오리진의 `127.0.0.1` 요청은 CORS와 LNA 대상입니다.

1. YouTube watch 캡션 경로의 동작을 기준선으로 고정합니다. 이 경로에서는 `tabCapture`를 열지 않습니다.
2. 사이트 없는 코어를 넣고, epoch·revision·큐·취소를 가짜 시계로 검사합니다.
3. 오디오 출력은 offscreen 한곳으로 모으고, 생성 이유는 `USER_MEDIA`를 포함해 30초 묵음 종료에만 의존하지 않습니다. 이유 조합의 실제 수명은 실측 항목으로 남깁니다.
4. 기존 YouTube 어댑터만 코어에 연결합니다.
5. 텍스트 읽기는 별도 모드로 한 사이트만 추가합니다.
6. 캡션 없는 VOD 캡처는 한 사이트에서 “따라 읽는 지연 모드”로만 추가합니다. 4문장 선행은 켜지 않습니다.
7. 라이브와 나머지 피드는 어댑터가 신원·광고·음소거를 구분한 뒤에 연결합니다.

숫자 지연 한도는 측정 전이므로 합격 조건이 아닙니다. 관찰 가능한 조건만 통과로 봅니다.

- 캡션 watch에서 seek 또는 stop 이후, 이전 generation의 소리가 나지 않습니다. 음절 홀드가 걸었다면 사용자의 일시정지 의도와 충돌하지 않고 홀드가 끝납니다.
- watch를 떠나면 캡처 스트림이 열려 있지 않습니다.
- 가짜 테스트에서 epoch 또는 revision이 다른 결과는 스케줄되지 않습니다. 스케줄 경쟁은 넣기 전이 아니라 재생 호출 직전에 다시 검사합니다.
- 엔진 대기는 모드별 상한에서 막히거나 명시적으로 실패합니다. 상한 없는 Node 작업을 성공으로 보지 않습니다.
- 큐 정책은 모드마다 다릅니다. 캡션 VOD는 유한 선행에서 생산자를 막고, 캡처 VOD는 이미 들은 작업만, 라이브는 재생하지 않은 항목을 버리며, 텍스트는 하나이고 화면에서 벗어나면 취소합니다.
- 캡처를 쓰는 순간 원음이 공식 동작대로 끊깁니다. UI는 첫 TTS 전에 “준비 중”이어야 하고, 원음 재연결 여부가 코드에 드러나야 합니다.
- 표식 톤 절차를 통과하기 전에는 캡처 fallback을 기본값으로 만들지 않습니다.
- 부정·소수·고유명사 문장은 슬롯 실패 시 무음입니다.
- 광고인지 모르거나 가청 영상이 둘이면 그 구간은 STT에 들어가지 않습니다.
- 권한을 주지 않은 사이트에는 스크립트가 주입되지 않습니다. YouTube 캡션 회귀는 그 사이트 권한만으로 동작합니다.

## 5. 지금 고정할 코어 계약

코어는 DOM, `chrome.*`, 모델, 사이트 URL을 모릅니다. 서비스 워커는 큐의 소유자가 아닙니다. 소유자는 offscreen 컨트롤러 또는 이미 있는 loopback 프로세스 중 하나이고, 재생 시계는 오디오를 실제로 트는 쪽에 있습니다. 늦은 응답은 epoch가 같아도 재생 직전 검사를 다시 통과해야 합니다.

```ts
type Mode = "vod-caption" | "vod-capture" | "live-capture" | "read-aloud";

interface Clock {
  mediaTime(): number | null; // read-aloud는 null
  paused(): boolean;
  hold(on: boolean): Promise<"held" | "unsupported">;
}

interface Session {
  epoch: number;
  mediaId: string; // 어댑터 불투명 id. URL 금지
  mode: Mode;
  hasFutureText: boolean;
  clock: Clock;
}

interface Cue {
  id: string;
  revision: number; // 라이브 자막 개정
  start: number | null;
  end: number | null;
  text: string;
  slots: { kind: "number" | "polarity" | "name"; value: string }[];
}

interface AudioOut {
  epoch: number;
  mediaId: string;
  cueId: string;
  revision: number;
  bytes: ArrayBuffer;
  durationSec: number;
}
```

불변 조건은 다섯 개입니다.

- `mediaId`가 바뀌거나, seek·stop·탐색·숨김·광고·음소거가 오면 `epoch`가 증가합니다. 진행 중 엔진 호출은 abort되거나, abort가 없으면 in-flight 1에서 새 호출이 이전 호출을 폐기합니다.
- 스케줄 조건은 epoch, `mediaId`, `revision`이 모두 같은 경우뿐입니다. 취소는 이미 예약된 오디오 소스의 `stop`을 포함합니다.
- `vod-capture`와 `live-capture`는 `start`가 이미 렌더된 시각보다 큰 cue를 만들지 않습니다. `hasFutureText === false`이면 선행 큐 깊이는 0입니다.
- `hold`는 `vod-caption`과, `hold`가 `"held"`를 반환한 `vod-capture`에서만 호출합니다. `"unsupported"`이면 음절 보존을 포기하고 늦으면 버립니다.
- 슬롯 검사가 실패하면 `AudioOut`을 만들지 않습니다.

어댑터가 낼 이벤트는 `session`, `cues`, `invalidate`, `end`가 전부입니다. 캡처 PCM은 코어 입력이 아니라 `vod-capture`/`live-capture` 전용 ingest가 cue로 바꾼 결과만 코어에 들어옵니다. 텍스트 게시물은 `read-aloud`이며 `hold`와 탭 캡처를 호출하지 않습니다.

지금 작성할 범위는 이 타입, 모드별 큐 상한, 재생 허가 함수, abort 토큰입니다. 플랫폼 어댑터와 탭 캡처 그래프는 이 계약 밖에 두고, YouTube 캡션 경로가 같은 허가 함수를 통과한 다음에만 다음 사이트를 붙입니다.
